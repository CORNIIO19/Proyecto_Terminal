Las limitaciones al hacer uso de plataformas como Notion, Obsidian, Google Docs, entre otras, es que no generan confianza a los usuarios en cuanto a privacidad, accesibilidad. Además, algunas de las herramientas requieren de una curva de aprendizaje para conocer la interfaz con la cual puedan generar notas o información. La curva de aprendizaje puede ser prolongada para lograr avances y cumplir con un objetivo especifico.

\vspace{.5cm}

Para lograr un uso satisfactorio para el usuario, se deben considerar las necesidades de estudiantes y profesionales como la organización del conocimiento y el acceso fácil a través de medios digitales sin importar el espacio físico en el que se encuentren representan un problema a resolver.

\vspace{.5cm}

Es por lo anterior que se requiere diseñar una aplicación que genere confianza al usuario, que además logre una conexión cercana entre el conocimiento y el usuario para así mejorar la accesibilidad, generar mayor confianza y mejorar la privacidad de la información.

\section{Escenario de uso}
\noindent En esta sección se plantea el escenario o contexto de uso de la aplicación, se presenta desde los problemas que tiene el usuario con sus notas hasta el caso de uso principal que resuelve este problema con la aplicacion \emph{Gestor inteligente para notas académicas} como se puedo ver en la figura \ref{fig:Contexto}.

\vspace{.5cm}

\noindent En la figura~\ref{fig:Contexto} podemos observar un flujo que describe el contexto de uso de la aplicacion \emph{Gestor inteligente para notas academicas}, en este se podra observar desde el planteamiento del problema que da paso a la aplicacion \emph{Gestor inteligente para notas academicas}, hasta el escenario principal en el que se podra usar y como se plantea resolver este problema antes planteado.

\vspace{.5cm}

Como punto de inicio podemos ver el principal actor que es el usuario Omar y las notas, en el \textbf{punto 1} de la figura \ref{fig:Contexto} se muesra como el usuario generá notas y apuntes de diferentes fuentes o diferentes situaciones, en este primer punto unicamente se muestra la generacion de las notas sin dar una organización o etiquetado despues pasamos en el mismo proceso a la colaboracion de las notas, en este el usuario busca complementar o verificar que sus notas sean correctas.

\vspace{.5cm}

Despues pasamos al \textbf{punto 2} en el que muestro el resultado del punto 1, aqui el usuario Omar acumula notas de diversos temas hasta tener grandes volumenes de notas, después en el \textbf{punto 3} el usuario a partir de estos conjuntos de notas que poseé, necesita consultarlas, generar nuevas o estudiar para reforzar los temas vistos, pero nos encontramos con tres principales problematicas que se pueden observar en el \textbf{punto 4}, estas probematicas son importantes ya que posteriormente nos permitiran presentar la solución de la aplicacion \emph{Gestor inteligente para notas academicas} y que se describen a continuacion:

\begin{itemize}
    \item \textbf{Transporte:} El usuario Omar desea consultar sus notas y apuntes mientras hace uso del transporte, esto dificulta el acceso, ya que el usuario Omar no se encuentra en un lugar donde pueda acceder facilmente a sus libros, cuadernos o documentos ya sean fisicos o digitales, agregando a que este no tiene un sistema centralizado en el cual recopilar sus notas.

    \item \textbf{Organización:} Si el usuario Omar no respeta un orden u organizacion de todas las notas generadas representa un problema, ya que esto dificulta su busqueda y retrazan acciones que desee hacer con las notas, como estudiar, complementar sus notas o encontrar puntos importantes como actividades pendiente o tareas pendientes.

    \item \textbf{Estudio:} El usuario Omar necesita estudiar ayudandose de las notas generadas pero muchas veces solo necesita estudiar de temas especificos, lo cual si el contenido de las notas no esta organizado o bien definido puede retrasar el estudio al dedicar mas tiempo en la busqueda de temas concretos u especificos.
\end{itemize}

\noindent Una vez mostradas estas problematicas podemos ver en el \textbf{punto 5}, como estas causan frustracion al usuario Omar ante la falta de organización, contexto o accebilidad. 

\vspace{.5cm}

A partir de estos problemas proponemos el principio de uso de la aplicacion \emph{Gestor inteligente para notas academicas} \textbf{punto 6}, en esta principalmente se propone centralizar las notas que el usuario acumule explicandolo con una pequeña formula: el usuario + grupos de notas + una aplicacion que las centralice, dando como resultado la creacion de una base de conocimiento \textbf{Punto 7}, siendo este el punto central de la solución como podemos ver en el \textbf{Punto 7}, de esta manera podemos resolver el problema de centralizacion (Transporte). 

\vspace{.5cm}

Posteriormente en el \textbf{Punto 8} se genera un sistema clasificador el cual clasifique las notas relacionandolas con su contenido, encontrando similitudes entre palabras clave o etiquetas, dando estructura y orden a las notas del usuario \textbf{punto 9} de esta manera logramos dar solucion al problema de organizacion (Almacenamiento), 

\vspace{.5cm}

De modo que con lo antes planteado podamos lograr generar un contexto o medio local, en el cual el usuario podra hacer consultas personalizadas mediante preguntas u oraciones en leguaje natural a la base de conocimiento, siendo esta la principal funcionalidad de la aplicacion que podemos ver en el \textbf{punto 10}, logrando de igual manera resolver el problema de consultas especifica (Estudio), haciendo que el usuario Omar logre poner mas tiempo en actividades como estudiar o mejorar sus notas. 

\vspace{.5cm}

El \textbf{Punto 10} se plantea mediante el uso de una aplicación la cual tenga la funcionalidad de un chat similar al de whatsapp, en este chat el usuario podra interactuar con un asistente de inteligencia artificial tipo chatbot haciendo preguntas, analisando sus notas o encontrando informacion especifica dentro de la base de conocimiento, como lo podemos ver en el \textbf{Punto 11} 

\vspace{.5cm}

Una vez que el usuario Omar haya interactuado con su base de conocimiento teniendo como intermediario el chat de la aplicacion \emph{Gestor inteligente para notas academicas} mostrado en el \textbf{Punto 11} el flujo muestra dos posibles resultados:

\begin{itemize}
    \item Primero como podemos ver en el \textbf{punto 13} en el cual si se encuentra informacion el chatbot nos contestara dando la informacion que encuentre unicamente en la base de conocimeitno del usuario.

    \item la segunda posibilidad mostrada en el \textbf{punto 14} en la que si el chatbot no encuentra nada informara al usuario y se le dara una recomendacion de que haga alguna nota o adjunte informacion nueva con relación a este tema.

\end{itemize}

De esta manera llegamos al final del contexto de uso de la aplicacion \emph{Gestor inteligente para notas academicas} mostrada en el \textbf{punto 15} en el que el usuario tendra un mejor acceso a la informacion con consultas totalmente personalizadas con información organizada y lo mas importante con informacion propia.

\section{Requerimientos}

\noindent Para lograr realizar la aplicacion \emph{Gestor inteligente para notas academicas} deberemos describir lo que la aplicacion debera hacer y como lo debera hacer, dentro del desarrollo de software podemos entender esto como los requerimientos, estos son las especificaciones detalladas que nos ayudaran a definir las funcionalidades y los propositos que se cumpliran al final del desarrollo de esta aplicación.

\vspace{0.5cm}

\noindent Por otra parte los requerimientos nos ayudaran a marcar pautas para lograr desarrollar una aplicacion funcional que resuelva las necesidades marcadas en secciones anteriores del documento.

\vspace{.5cm}

\noindent Los requerimientos se pueden dividir en 2, los requerimientos funcionales (RF) que podemos entender como las funcionalidades, actividades o servicios que debera hacer la aplicacion al final del desarrollo, en resumen marcan el comportamiento de la aplicacion, al igual que nos ayudara a definir los casos de uso de la aplicacion.

\vspace{.5cm}

Por ultimo los requerimientos no funcionales (RFN) que no son mas que el como la aplicacion debera hacer estos comportamientos asi mismo las restricciones que debera seguir (cualidad, rapidez, seguridad, tolerancia a fallos, etc), al igual que los requerimientos funcionales los requerimientos no funcionales nos ayudaran a definir una arquitectura para el sistema. A continuacion detallare los requerimientos funcionales y no funcioanles que seguire en el desarrollo de la aplicación \emph{Gestor inteligente para notas academicas}.  




\subsection{Funcionales}

\begin{description}
    \item[RF1.] El usuario podra crear una cuenta personal dentro de la aplicacion \emph{Gestor inteligente para notas academicas} vinculada con correo eletronico o numero de telefono.

    \item[RF2.] El usuario podra modificar la informacion de su cuenta en la aplicacion \emph{Gestor inteligente para notas academicas}.

    \item[RF3.] El usuario podra modificar, actualizar informacion de su cuenta personal dentro de la aplicacion \emph{Gestor inteligente para notas academicas}.
    
    \item[RF4.]El usuario podra verificar su cuenta mediante procesos como factor de doble autenticacion, vinculando su cuenta con algun numero de telefono, algun correo electronico o generando codigos de verificación.
    
    \item[RF5.] El usuario podra adjuntar notas digitales dentro del almacenamiento de la aplicación.
    \item[RF6.] El usuario podra eliminar notas digitales del almacenamiento de la aplicación.
    \item[RF7.] EL usuario podra actualizar sus notas digitales dentro de la aplicación.
    \item[RF8.] El usuario podra crear bases de conocimiento personalizadas ajustandolas a sus necesidad y agregando las notas que requiera para esto.
    \item[RF9.] El usuario podra editar las notas que formen parte de la base de conocimientos personalizada eliminandolas o actualizandolas segun lo requiera.
    \item[RF10.] El usuario podra eliminar las bases de conocimiento personalizadas.
    \item[RF11.] El usuario realizara busquedas de notas o archivos especificos que se alamenen dentro de la aplicación.
    \item[RF12.] El usuario podra organizar de manera personalizada y manual las notas que adjunte dentro de la aplicacion, permitiendole crear directorios con sus notas.
    \item[RF13.] El usuario podra consultar sus notas mediante un chat de texto sus notas de distintas bases de conocimiento.
    \item[RF14.] El usuario solicitara resumenes de las bases de conocimiento permitiendole conocer los temas que componen la base de conocimiento o las fechas en las que se realizaron las notas.
    \item[RF15.] El usuario y los colaboradores calificaran las notas de otros usuario, logrando parametrizar las notas de los usuarios, caliicandolas por diferentes marcas ejemplo: Congruencia, legibilidad, continuidad, claridez, entre otras.
    \item[RF16.] El usuario tendra disponible la opcion de sincronizar sus bases de conociento creadas en diferentes dispositivos.
    \item[RF17.] El usuario podra configurar las opciones de privacidad con su cuenta y con sus bases de conocimiento.
    \item[RF18.] La aplicacion notificara al usuario acerca de actividades que se realicen con las notas, las colaboraciones con otros usuarios o cambios en la informacion de su cuenta.
    \item[RF19.] El usuario podra agregar y sincronizar nuevos dispositivos ejemplo: Telefonos, computadoras o laptops.
    \item[RF20.] El usuario podra calificar a los colaboradores de tipo expertos para asi poder crear una escala de calificacion.
    \item[RF21.] Los usuarios podran aceptar cambios que los colaboradores recomienden o hagan dentro de sus notas de las bases de conocimiento.
    \item[RF22.] Los usuarios podran agregar nuevos colaboradores que sean de confianza para facilitar los cambios o recomendacion que estos puedan hacer.
    \item[RF23]. Los usuarios podran realizar copias de seguridad, sobre sus bases de conocimientos, conversaciones con el chatbot y documentos adjuntados.
    \item[RF24.] El usuario podra adjunar copias de seguridad de sesiones anteriores y de esta manera poder recuperar notas y bases de conocimiento.
    \item[RF25.] La base de conocimientos almacenara distintas bases de conocimiento creadas por el sistema clasificador y por el usuario.
    \item[RF26.] El sistema clasificador generara bases de conocimiento, al relacionar las notas y documentos que el usuario adjunte.
    \item[RF27.] El sistema clasificador organizara las notas y documentos que el usuario adjunte clasificandolas y organizandolas con diferentes filtros dependiendo su contenido.
    \item[RF28.] El sistema clasificador relacionara las notas del usuario de acuerdo a las similitud del contenido o por medio de etiquetas que permitan relacionar cada documento.
    \item[RF29.] El colaborador y cualquier usuario que tenga el rango colaborador podra calificar las notas de los usuarios que tenga visibles su notas, calificandolas de acuerdo a distintos criterios.
    \item[RF30.] El colaborador podra solicitar o hacer una solicitud de cambios en las notas que tengan visibilidad publica con otros usuarios.                           



\end{description}

\subsection{No Funcionales}

\begin{description}

    \item[RNF1.] Toda la información deberá almacenarse de forma local en el dispositivo del usuario.
    \item[RNF2.] Cuando el usuario cree su cuenta en la aplicaccion esta debera de admitir la creacion de la cuenta con correo y telefono del usuario obligatoriamente.
    \item[RNF3.] Cuando el usuario con cuenta existente cierre la sesion en su dispositivo e ingrese de nuevo al dispositivo, este debera de autenticarse por medio de doble factor de autenticacion.
    \item[RNF4.] Para ofrecer una doble autenticacion al usuario, la aplicacion debera ofrecer codigos de seguridad a modo de llaves digitales.
    \item[RNF5.] La informacion que el usuario agregue a la aplicacion se debera de almacenar de manera local en todos los casos posibles.
    \item[RNF6.] Cuando el usuario gestione las notas dentro de la aplicacion, la aplicacion debera notificar al usuario cualquier cambio que se haga con los archivo o informacion.
    \item[RNF7.] Cuando el usuario quiera eliminar su cuenta de forma permanente, la aplicacion debera generar un codigo para verificar la accion de eliminar del usuario.
    \item[RNF8.] Cuando el usuario cree una nueva base de conocimienos la aplicacion debera de notificar mediante un pop-up la informacion de la nueva base de conocimiento.
    \item[FNF9.] La aplicacion debera soportar la creacion de al menos 10 bases de conocimiento, creadas manualmente por el usuario.
    \item[RNF10.] La aplicacion debera permitir la carga de documentos pequeños a el almacenamiento de la aplicacion.
    \item[RNF11.] La aplicacion debera admitir la carga de documentos con extension: pdf, md, txt.
    \item[RNF12.] Cuando el usuario visualice las notas dentro de la aplicacion, se abrira una nueva ventana mostrando el contenido de las notas.
    \item[RNF13.] Al momento de hacer resumenes la aplicacion debera recopilar al menos el 70\% de la informacion de la base de conocimientos.
    \item[RNF14.] Cuando el usuario consulte sus notas o tenga conversaciones con el chatbot, la aplicacion debera tener un apartado separado en el que solo se muestre el chat con el usuario. 
    \item[RNF15.] El almacenamiento de las bases de datos debera de estar sincronizado con el dispositivo principal del usuario. 
    
    \item[RNF16] Al momento de iniciar sesion en distintos dispositivos la aplicacion debera de pedir al usuario designar un dispositivo principal.
    
    \item[RNF17.] Para aceptar a un usuario como colaborador, se tendra que mandar una notificacion de solicitud.
    
    \item[RNF18.] El almacenamiento de notas digitales deberá garantizar tolerancia a fallos mediante técnicas de respaldo automático y redundancia.
    
    \item[RNF19.] El sistema deberá permitir una organización estable y consistente de notas, evitando duplicidades y asegurando integridad referencial entre notas y bases de conocimiento.
    
    \item[RNF20.] El sistema deberá garantizar que el acceso a notas calificadas o colaborativas se dé únicamente bajo los permisos establecidos, evitando accesos indebidos por usuarios no autorizados.
    \item[RNF21.] La aplicación deberá ser compatible con los principales sistemas operativos móviles y de escritorio, garantizando un comportamiento consistente en todos los dispositivos soportados
    \item[RNF22.]La interfaz de usuario deberá ser intuitiva, responsiva y accesible, permitiendo navegación fluida y tiempos de carga menores a 10 segundos por pantalla.  
    \item[RNF23.] La relación entre notas, documentos y etiquetas deberá garantizar integridad lógica, evitando rupturas de vínculos o referencias.
    \item[RNF24.] El sistema clasificatorio deberá procesar y reorganizar notas en un tiempo no mayor a 15 segundos por lote bajo condiciones normales.  
    \item[RNF25.] El sistema clasificatorio deberá operar con precisión, garantizando que la organización automática de notas mantenga coherencia semántica y no altere el contenido original.
    \item[RNF26.] El sistema deberá permitir la adición o eliminación de colaboradores con validación de permisos y asegurando que los accesos sean consistentes con la configuración de privacidad del usuario.
    \item[RNF27.] El sistema deberá contar con mecanismos de protección contra accesos no autorizados, fuerza bruta y manipulación de datos tanto en cuentas como en colaboraciones.
    
    \item[RNF28.] Las operaciones de colaboración (calificar, editar, sugerir cambios) deberán registrarse en un historial verificable, manteniendo trazabilidad y evitando modificaciones no autorizadas.

\end{description}

    \caption{Arquitectura del sistema propuesto}

La arquitectura del sistema propuesto se puede observar en la figura \ref{fig:Arquitectura}, en la cual se muestran los diferentes componentes que conforman el sistema.

\vspace{.5cm}

Esta arquitectura se basa en principalmente en 3 arcquitecturas: Hexagonal, Limpia, Basada en servicios y Arquitectura Offline que permite el desarrollo del comportamiento, objetivos y el mantenimiento del sistema. Los componentes principales incluyen:

\begin{itemize}
    \item \textbf{Presentacion:} Donde los estudiantes y profesores interactúan con el sistema, todas las posibles ventanas de la aplicacion.
    \item \textbf{Capa de aplicacion:} Esta capa define qué se hace, no cómo se hace las diferentes funcionalidades, aquí vive la lógica que responde a todas las acciones del usuario.
    \item \textbf{Capa de Dominio:} En esta definimos lo que la aplicacion es o su estructura, independientemente de las tecnologias que ocupemos, ademas de garantizar el comportamiento de la aplicacion y definir las estructuras de los datos principales, de igual forma se definen reglas, restricciones y validaciones.
    
    \item \textbf{Infrestructura:} La infraestructura es la encargada de conectar la aplicación con cualquier tecnología externa que definamos despues.
    
    \item \textbf{Seguridad:} En esta capa o modulo se busca proteger datos en reposo, en tránsito y controlar accesos y colaboraciones.
    
    \item \textbf{Servidor de Sincronizador:} Esta cumplira con recibir eventos desde dispositivos, validar, aplicar en base de sincronización autorizada ademas sincronizar cambios a otros dispositivos

    \item \textbf{Modulos Offline:} con esta capa se busca permitir el 100\% de operaciónes sin red y manejar la transición a sincronizado cuando el usuario vuelva a tener conexion.
\end{itemize}
